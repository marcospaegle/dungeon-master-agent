# Glossary

**Adaptive specializing interpreter** — CPython 3.11+ feature replacing generic bytecode with type-specialised instructions for hot code (Ch 1, 2)
**Amdahl's law** — max speedup from parallelism is limited by the serial portion (Ch 1)
**Amortized O(1)** — average cost per op is constant even though some ops (resize) are expensive (Ch 3, 4)
**Binary search** — O(log n) search in sorted data; `bisect` module (Ch 3)
**Bus width / frequency** — data per transfer vs transfers per second; together set bus speed (Ch 1)
**Bytecode** — instructions run by CPython's stack VM; inspect with `dis` (Ch 2)
**cProfile** — built-in function-level profiler; `-s cumulative`, `-o stats` (Ch 2)
**Copy and patch JIT** — 3.13 JIT pasting runtime addresses into prebuilt LLVM "stencils" (Ch 1)
**deque** — O(1) appends/pops at both ends (Ch 5)
**Dynamic array** — resizable array with overallocation; Python `list` (Ch 3)
**Embarrassingly parallel** — no data shared between work items (e.g. Julia set pixels) (Ch 2)
**Entropy (hash)** — how evenly a hash spreads values; max entropy = ideal hash (Ch 4)
**Freelist** — cache of freed objects for fast reuse; tuples sizes 0–20 × 2,000 (Ch 3)
**GIL** — global interpreter lock: one Python instruction at a time per process (Ch 1)
**Generator** — function with `yield` producing values lazily (Ch 5)
**Hash table (open addressing)** — array indexed by masked hash, with perturbed probing (Ch 4)
**Heavy data** — cost of moving data; minimize moves (Ch 1)
**Hyperthreading** — presents a virtual second CPU; up to ~30% gain (Ch 1)
**IPC / clock speed** — instructions per cycle / cycles per second (Ch 1)
**kernprof / line_profiler** — line-by-line CPU profiler (Ch 2)
**Lazy evaluation** — compute only when a value is requested (Ch 5)
**Load factor** — how full a hash table is; dict < 2/3, set < 3/5 (Ch 4)
**Mask** — `size-1` bitmask truncating a hash to a table index (Ch 4)
**memory_profiler / mprof** — line-by-line and time-sampled RAM profilers (Ch 2)
**Native vs Python vs system time** — Scalene's split of where time goes (Ch 2)
**No-op @profile** — dummy decorator so tests run without profilers (Ch 2)
**Online / single-pass algorithm** — needs each datum once; generator-friendly (Ch 5)
**Out-of-order execution** — CPU runs independent instructions early (Ch 1)
**Overallocation** — extra capacity reserved by lists; `(N + (N>>3) + 6) & ~3` (Ch 3)
**py-spy** — sampling profiler attaching to running processes (Ch 2)
**Scalene** — low-overhead combined CPU/memory/GPU profiler (Ch 2)
**SIMD / vectorization** — one instruction on multiple data (Ch 1)
**SipHash 1-3** — hash algorithm for non-int Python objects (Ch 4)
**SnakeViz** — visualizer for cProfile stats (Ch 2)
**Specialist** — colours specialised/adaptive bytecode regions (Ch 2)
**Static array** — fixed-size array; Python `tuple` (Ch 3)
**Timsort** — hybrid insertion/merge sort; O(n) best, O(n log n) worst (Ch 3)
**Turbo Boost** — temporary CPU overclock that skews benchmarks (Ch 2)
**VizTracer** — time-based interactive call-stack tracer (Ch 2)
**Welford's algorithm** — one-pass online mean/variance (Ch 5)
